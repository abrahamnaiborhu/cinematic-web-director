# Changelog

Versioned GitHub releases use three-part tags. v0.2.0 is the first published release of the revised v0.2 package and is marked as a development pre-release.

## [0.3.0] - Unreleased

### Added

- Design-direction protocol for deriving presentation from subject, audience, content and intended visitor understanding.
- Redesign-intent clarification, separation of required facts/functionality from inherited styling, and reasons for consequential retained or replaced choices.
- Content-based concept alternatives, representative composition review before choreography, and qualitative critique of specificity, inheritance, reading comfort and motion purpose.
- Six synthetic evaluation cases with client inputs/materials separated from reviewer criteria.
- Project-template fields for redesign freedom, provisional structure, inherited choices, inspected compositions and design revisions.

### Changed

- Checkpoint A distinguishes fixed structure from provisional exploration; checkpoint B includes content fit, composition evidence and inherited-choice rationale.
- No metaphor, signature-interaction quota, typography style or prescribed scroll effects are universal design requirements. Client-defined constraints and approved sprint boundaries remain authoritative.
- Package integrity now requires nonempty design-direction guidance; ZIP payload includes the protocol and evaluation cases.

### Validation and limits

- Offline tests cover missing/blank design guidance and inclusion of the new distribution resources alongside existing preflight and packaging behavior.
- Manual scenario review checks instruction consistency, including limited refreshes and approved-sprint continuation. Independent session evaluations and rendered redesign trials remain pending.
- This candidate is prepared locally. Building a ZIP does not publish it or replace a previously installed v0.2.0 skill.

## [0.2.0] - 2026-10-14

### Added

- Adaptive discovery for new landing pages, portfolios, multi-page product websites and existing-site redesigns.
- Existing-material inventory, factual-source clarification, copy development, site structure and visitor journeys.
- Storyboarding, bounded approved motion experiments, approved sprint batches and controlled refinement.
- Explicit model agreements, handoff records, configuration authorization and honest host/identity limitations.
- Beginner tutorial, release packaging helper, versioned ZIP and SHA-256 checksum.
- Regression coverage for preflight evidence, portability, application scope, release captures and package construction.

### Changed

- Intent clarification precedes project-specific preflight; missing implementation tooling does not prevent discovery.
- Narrative structure and motion follow the website's purpose. Five acts, a dramatic climax, a single CTA and literal reverse scrolling remain optional.
- Approved sprint plans authorize continuous execution within scope, including verification, critique and refinement.
- Creative requirements and architecture are evaluated together, including justified additions and migrations.
- Preflight report schema is 1.1, with evidence scope, selected source, application inventory and a separate creative-approval limitation.
- Core/performance GSAP guidance is the baseline; framework guidance and explicitly selected topics follow the approved treatment.
- Release image evidence is limited to the documented PNG encodings; provenance and interaction results remain agent-attested.

### Fixed

- Agent identity declarations and environment inference no longer imply independently verified identity.
- Package integrity includes both references and all four templates.
- Custom Codex skill homes and explicit skill roots are supported; quoted skill names require an exact metadata match.
- Dependencies from sibling applications no longer satisfy the selected application's requirements.
- Static HTML/CDN projects and scoped session observations have an explicit path through preflight.
- Optional tools do not create readiness caveats; declarations do not prove installation.
- Malformed manifests, blank briefs hiding valid equivalents, invalid screenshot payloads and duplicate viewport evidence are handled conservatively.
- Non-GSAP batches do not receive unnecessary GSAP setup advice.

### Validation and limits

- Offline unit/integration tests and an extracted-package smoke check accompany this release.
- Manual instruction walkthroughs cover six representative scenarios.
- Live cross-agent portability, independent behavioral evaluation and rendered website trials remain unperformed.
- The optional external skill validator requires PyYAML, which is not a dependency of this package. Basic frontmatter and local-link checks can run without it.

## v0.1 baseline

- Executable offline eight-check preflight, initial creative workflow and four project templates.
