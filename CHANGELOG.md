# Changelog

Versioned GitHub releases use three-part tags. v0.2.0 is the first published release of the revised v0.2 package and is marked as a development pre-release.

## [0.8.0] - 2026-10-24 (development pre-release)

### Added

- A standalone motion companion comparing persistent recognition, collection reorganization and a deliberate immediate cut, using original fictional artwork and optional stillness. Playback is opt-in with pause/replay/finish, return, direct/history entry, reduced motion and responsive composition.
- An interpretation workflow connecting confirmed input, recommendations, the visitor experience and uncertainty. Demo reactions remain distinct from client concepts, bounded prototype approval and production authorization.
- Local browser/lifecycle verification and continuing-conversation evaluation alongside package-integrity checks. No public release or client website deployment is implied.

## [0.7.5] - Unreleased; first published in 0.8.0

### Added

- A bundled standalone HTML taste guide with eight original fictional static compositions, mixed reactions/reasons and separate eccentricity, artistry and motion preferences. Outside preferences and uncertainty remain valid; no style score, preset selection or approval is inferred.
- Local copyable provisional notes, no-script access, print notes and dependency-free browser verification. The guide uses no remote fonts/assets, tracking or answer persistence.
- Taste-discovery routing, project-script fields, package-integrity checks and an evaluation record. Static samples do not claim motion evidence; ambitious preferences retain accessibility/device/performance requirements.

## [0.7.1] - Unreleased; first published in 0.8.0

### Changed

- Strengthened discovery readiness before full concepts: distinguish answered, delegated and consequential unknown decisions; deepen ambiguous answers and discuss visual/motion experience instead of silently choosing defaults.
- Kept short illustrative ideas available for teaching and questions, with explicit exceptions for immediate provisional concepts, complete briefs and approved work. Direct sitemap/copy-placement requests remain answerable without a forced design interview.
- Added a concise discovery-readiness record to the project script. Local conversational checks supplement the earlier one-shot planning trials; published v0.7.0 is unchanged.

## [0.7.0] - 2026-10-22 (development pre-release)

### Added

- Whole-experience planning before detailed choreography: real readiness/loading, visitor control, recovery, route/return and lifecycle ownership. Optional loaders have explicit release and bounded recovery behavior.
- Project-specific measurable performance budgets and an early connected production slice, with proportionate planning for simple sites and explicit runtime-evidence limits.
- Required jcodemunch-first supported source exploration for code-dependent work, with project identity/freshness checks, focused retrieval and incremental refresh. Unsupported material/live edit confirmation can use targeted native reads; unavailable MCP access requires repair or an approved bounded fallback.
- Shared Codex/Claude Code setup guidance and explicit licensing/environment boundaries. Creative-only work and empty projects may defer indexing. The separately installed server is not included in the skill ZIP.
- An agent-side index readiness requirement within project-environment check 4, preserving eight preflight categories. The offline checker verifies the guidance resource, not a live MCP connection.

## [0.6.0] - 2026-10-20 (development pre-release)

### Added

- A phase-scoped Ponytail adaptation for approved implementation, in-scope refactoring and engineering review: inspect connected behavior, reuse adequate tools, preserve lifecycle/error handling and verify meaningful failure cases.
- Explicit preservation of approved creative behavior, device treatments and accessibility while simplifying implementation. Discovery and art direction retain their creative scope.
- Pinned upstream attribution and MIT license; the adaptation works locally without installing Ponytail's session-wide prompt, hooks or host-specific features.
- Contextual handoff direction: choose the content relationship and connection mechanism before timing variants; scope client preferences to the situation and justify recurrence or variation. A poster-study preference for B does not establish an overshoot default elsewhere.

### Validation and limits

- Two baseline and three updated fresh-context discovery sessions, each with a client continuation; contextual mechanisms and rhythm variants were distinguished while the calm product control stayed static. These small written trials do not establish causal artistic improvement.
- One approved poster-motion comparison, two design refinements and 15 passing local Chrome check groups at phone, compact-laptop and larger viewports. The client preferred B for that poster situation; the choice is not a universal overshoot recipe or whole-site adoption.
- An independent source-review trial found incomplete listener teardown while preserving approved choreography. It is bounded evidence, not proof of general review effectiveness or upstream benchmark savings.
- Published with the complete skill ZIP, tutorial, separate checksums and optional evaluation-evidence bundle. The package includes v0.6 reports, fixtures and the inspectable motion study; machine-local prefixes are normalized in public evidence.
- Broader rendered art direction, real-client outcomes, cross-host/fallback-model behavior and physical-device/cross-browser compatibility need further evidence. The full Ponytail plugin, session modes and hooks are not installed by this skill.

## [0.5.0] - 2026-10-19 (development pre-release)

### Added

- A conditional creative-review guide and adaptable review-package template connecting a focused client decision to actual material, imagery direction, visitor tasks and observable runtime cases.
- Synthetic portfolio, landing-page and product fixtures and a controlled fresh-context evaluation plan. Baseline and candidate outcomes are recorded separately from human/client and device evidence.
- Review-resource integrity and packaging checks, preserving all eight preflight categories and existing approval/model boundaries.

### Validation and limits

- Offline checks validate the checker and archive, not design quality. Behavioral and rendered-study evidence is reported with its actual scope and unresolved criteria.
- Three baseline and three candidate fresh-context discovery trials are complete; both versions originated motion ideas. Candidate follow-ups made visitor/runtime planning explicit, while baseline product supplied generated visual boards. No causal quality improvement is inferred from these small samples.
- One client-approved synthetic motion study received a design refinement, 15 passing local Chrome checks and an independent synthetic newcomer review. Human/client adoption and cross-browser/physical-device evidence remain open; see the result report.
- Published as a development pre-release with the skill ZIP, standalone tutorial, checksums and optional evaluation-evidence bundle. It incorporates the v0.3, v0.4 and v0.4.1 work that was not released separately.
- Creative range and distinctive motion remain areas for further development; this release establishes bounded workflow evidence, not outstanding art direction or universal device compatibility. No live client website is changed by this skill update.

## [0.4.1] - Included in 0.5.0

### Fixed

- Generic mobile requirements now lead to explicit phone, compact-laptop/short-height and larger-screen composition/motion treatments from early design.
- Important effects gated to large viewports require a justified smaller-screen alternative rather than an automatic scaled or static version.
- Device coverage distinguishes viewport size, input capability, reduced-motion preference, browser/OS and measured hardware behavior.
- Platform planning explicitly considers Android, iOS/iPadOS, Windows, macOS and Linux where relevant, with representative browser/version targets and shared-component regression checks beyond the platform of a reported issue.
- Functional UI glyphs receive cross-platform review; existing SVG icons or a reusable vector component are preferred when stable geometry/color is needed. Intentional content emoji remain valid.
- Release guidance explicitly separates the two-PNG preflight floor from the agreed device/browser acceptance matrix.

### Added

- Device-experience reference with representative viewport coverage and an accessible decorative SVG-arrow example.
- Four evaluation cases for responsive choreography, iPhone arrow presentation, incomplete QA evidence and wide touch devices.
- Additional platform-scope evaluation to prevent a reported iPhone bug from narrowing Android and desktop design/testing requirements.
- Template fields for supported versus tested environments, device-specific choreography, icon rendering and remaining evidence gaps.

### Validation and limits

- Offline regressions cover required device guidance and complete packaging alongside existing behavior.
- Client-supplied screenshot/browser report and fresh public-source inspection grounded the update. Real iPhone reproduction, live website fixes and candidate device-motion trials remain pending.
- The update is a local skill candidate. Its construction does not modify a separate website or publish a GitHub release.

## [0.2.0] - 2026-10-14

### Added

- Adaptive discovery for new landing pages, portfolios, multi-page product websites and existing-site redesigns.
- Existing-material inventory, factual-source clarification, copy development, site structure and visitor journeys.
- Storyboarding, bounded approved motion experiments, approved sprint batches and controlled refinement.
- Explicit model agreements, handoff records, configuration authorization and honest host/identity limitations.
- Beginner tutorial, release packaging helper, versioned ZIP and SHA-256 checksum.
- Regression coverage for preflight evidence, portability, application scope, release captures and package construction.

### Changed

- Intent clarification precedes project-specific preflight; missing implementation tooling does not prevent discovery.
- Narrative structure and motion follow the website's purpose. Five acts, a dramatic climax, a single CTA and literal reverse scrolling remain optional.
- Approved sprint plans authorize continuous execution within scope, including verification, critique and refinement.
- Creative requirements and architecture are evaluated together, including justified additions and migrations.
- Preflight report schema is 1.1, with evidence scope, selected source, application inventory and a separate creative-approval limitation.
- Core/performance GSAP guidance is the baseline; framework guidance and explicitly selected topics follow the approved treatment.
- Release image evidence is limited to the documented PNG encodings; provenance and interaction results remain agent-attested.

### Fixed

- Agent identity declarations and environment inference no longer imply independently verified identity.
- Package integrity includes both references and all four templates.
- Custom Codex skill homes and explicit skill roots are supported; quoted skill names require an exact metadata match.
- Dependencies from sibling applications no longer satisfy the selected application's requirements.
- Static HTML/CDN projects and scoped session observations have an explicit path through preflight.
- Optional tools do not create readiness caveats; declarations do not prove installation.
- Malformed manifests, blank briefs hiding valid equivalents, invalid screenshot payloads and duplicate viewport evidence are handled conservatively.
- Non-GSAP batches do not receive unnecessary GSAP setup advice.

### Validation and limits

- Offline unit/integration tests and an extracted-package smoke check accompany this release.
- Manual instruction walkthroughs cover six representative scenarios.
- Live cross-agent portability, independent behavioral evaluation and rendered website trials remain unperformed.
- The optional external skill validator requires PyYAML, which is not a dependency of this package. Basic frontmatter and local-link checks can run without it.
