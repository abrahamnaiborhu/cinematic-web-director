# v0.7.0 validation results

Release scope: whole-experience planning and required supported-source exploration. Existing website study runtimes were not changed. Publication is a development pre-release; these checks do not certify broad creative improvement or website runtime performance.

## Local verification

All **45 offline tests** pass in the source checkout and extracted distribution. The skill validator passes using an existing isolated Python environment with PyYAML. The 75-file distribution is checked against source bytes and local Markdown targets. Required guidance includes `EXPERIENCE_SYSTEM.md`; missing and blank versions were shown to fail the added check before implementing the resource gate. The checker retains eight categories and does not inspect live MCP connections or certify lifecycle/performance plans.

[Whole-experience guidance](../references/EXPERIENCE_SYSTEM.md) routes through the entrypoint, discovery/readiness workflow and existing project/treatment/review templates. The director proposes connected readiness, interaction, navigation/return and recovery behavior before detailed choreography, with project-specific performance budgets. It preserves scope, creative ambition and approval boundaries; a loader, new framework/state library or coded study is not mandatory.

[jcodemunch integration evidence](JCODEMUNCH_INTEGRATION_PLAN.md) distinguishes global registration, stdio protocol verification and actual session exposure. Non-commercial use was confirmed by the client; the upstream server is separately installed/licensed and is not redistributed.

## Bounded behavioral validation

Two fresh-context synthetic planning trials used an isolated snapshot of the revised skill and raw client requests. Neither received the suspected weakness, expected answer or reviewer criteria. Each was limited to a local client-facing planning response, with no website implementation or external actions.

| Request | Observed response | Limits |
|---|---|---|
| Video-heavy motion-designer portfolio, phones and laptop, moving-poster opening | Proposed a poster-to-gallery connection, useful immediate content, required versus deferred media, interruption/return handling, one active preview, local failure recovery, proposed byte/timing budgets and an early arrival → gallery → case study → Back slice | No media inspected, visual composition rendered, budget measured or device behavior exercised; response is lengthy |
| Small one-page pottery exhibition with six photographs and subtle motion | Recommended static HTML/CSS, a small optional entrance, immediately usable dates/address/RSVP, no scroll wait, image budgets, ordinary return navigation and slow/failure checks | No artwork inspected or layout rendered; byte targets remain proposals and network conditions need greater precision before production |

Both outputs explicitly distinguish proposed direction from observed website behavior. The simple request did not acquire a mandatory loader, router, state library or continuous animation. The portfolio connected its supplied opening idea to substantive content and return behavior rather than treating the opening as the whole website. These observations support the narrow routing/planning change; two uncontrolled samples do not establish causal improvement, reliable compliance across models/hosts or human usability.

The optional `cinematic-web-director-v0.7.0-evidence.zip` release asset contains raw requests, actual responses, discovery reports, the instructions used and a hash manifest. Local path prefixes in reports are normalized with original/public hashes retained. Final instruction/reference bytes used by the trials are compared with the release; website runtime sources were not changed.

## Review and remaining limits

Reviewed entrypoint routing, lifecycle and approval boundaries, template integration, source-exploration licensing/coverage, required-resource failure behavior and archive exclusions. The new guidance does not prescribe loaders or fixed performance limits, authorize additional prototypes, or imply that offline checks prove runtime behavior. No blocking finding remains in this scoped review.

No new browser, physical-device, production deployment or independent human study was performed. The previous v0.5/v0.6 studies remain historical evidence for their own builds. Exact evaluator model/reasoning identity was not independently attested; no model switch or fallback was requested. Publication does not automatically configure MCP on another user's machine.
